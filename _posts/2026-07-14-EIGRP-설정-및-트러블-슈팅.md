# Packet Tracer EIGRP 구축 및 트러블슈팅

## 인터페이스 설정부터 기본 경로 재배포, DNS·HTTP·FTP 통신까지

## 1. 들어가며

이번 Packet Tracer 실습에서는 서울 본사, 경기 지사, 광주 지사를 EIGRP AS 100으로 연결하고, 서울 본사의 R1을 통해 ISP 및 외부 서버에 접속하도록 구성한ek..

최종적으로 다음 통신이 가능해야 한다.

```
서울·경기·광주 내부 PC 간 Ping
각 지사 PC → 서울 내부 서버 Ping
각 지사 PC → www.korea.com 접속
각 지사 PC → 외부 서버 198.133.219.1 Ping
각 지사 PC → www.cisco.com 접속
각 지사 PC → 외부 FTP 서버 접속
```

하지만 업로드된 초기 파일을 분석한 결과, 현재 상태에서는 통신이 되지 않는 것이 정상이다.

핵심 이유는 다음과 같다.

```
R1, R2, R3 인터페이스에 IP 주소가 없음
관련 인터페이스가 shutdown 상태
R1에는 EIGRP 프로세스만 있고 network 명령이 없음
R2와 R3에는 EIGRP 설정이 없음
내부 PC와 내부 서버에 IP 주소가 설정되지 않음
R1의 외부 기본 경로가 설정되지 않음
EIGRP를 통한 기본 경로 재배포가 설정되지 않음
R1의 일부 running-config가 startup-config에 저장되지 않음
```

따라서 이번 예제는 다음 순서로 구성하고 검증해야 한다.

```
주소 계획 확인
→ 라우터 기본 설정
→ 인터페이스 설정
→ 직결 구간 테스트
→ PC·서버 주소 설정
→ EIGRP 이웃 형성
→ 내부 라우팅 확인
→ 내부 서비스 확인
→ R1 기본 경로 설정
→ EIGRP 기본 경로 재배포
→ 외부 Ping·DNS·HTTP·FTP 테스트
→ 설정 저장
```

# 4. 초기 파일 상태 분석

## 4.1 R1의 현재 상태

R1의 running-config에는 EIGRP 프로세스가 생성되어 있지만 실제 network 명령은 없다.

```
router eigrp 100
 auto-summary
```

이 설정만으로는 어떤 인터페이스에서도 EIGRP가 동작하지 않는다.

또한 인터페이스는 다음 상태다.

```
interface FastEthernet0/0
 no ip address
 shutdown
!
interface FastEthernet0/1
 no ip address
 shutdown
!
interface Serial1/0
 no ip address
 shutdown
!
interface Serial1/1
 no ip address
 shutdown
```

---

## 4.2 R2와 R3의 현재 상태

R2와 R3에는 EIGRP 프로세스 자체가 없다.

인터페이스도 모두 다음과 같은 상태다.

```
no ip address
shutdown
```

따라서 현재 상태에서는 다음 항목이 모두 불가능하다.

```
PC에서 기본 게이트웨이 Ping
라우터 간 직결 Ping
EIGRP Hello 교환
EIGRP 이웃 관계 형성
원격 네트워크 경로 학습
```

---

## 4.3 내부 PC와 서버

서울, 경기, 광주 내부 PC와 서울 내부 서버에는 IP 주소가 설정되지 않은 상태다.

반면 ISP와 외부 서버는 이미 다음과 같이 구성되어 있다.

```
ISP F0/0: 198.133.219.254/24
ISP F0/1: 61.41.162.130/30

외부 서버:
IP      198.133.219.1/24
Gateway 198.133.219.254
DNS     198.133.219.1
```

외부 서버에서는 HTTP, FTP, DNS 서비스가 활성화되어 있다.

FTP 계정은 다음과 같다.

```
Username: cisco
Password: cisco
```

## 8.4 상태별 장애 판단

### administratively down/down

```
Serial1/0 administratively down down
```

원인:

```
no shutdown 누락
```

조치:

```
interface serial 1/0
 no shutdown
```

### down/down

```
Serial1/0 down down
```

확인 항목:

```
반대편 인터페이스가 shutdown인지
케이블이 올바른 포트에 연결됐는지
라우터 전원이 켜져 있는지
```

### up/down

```
Serial1/0 up down
```

확인 항목:

```
DCE 측 clock rate
양쪽 encapsulation 일치
반대편 Serial 인터페이스 설정
```

DCE 여부는 다음 명령으로 확인할 수 있다.

```
show controllers serial 1/0
```

# 13. 왜 R1 F0/1을 EIGRP에 포함하면 안 되는가

R1 F0/1은 내부 EIGRP 도메인이 아니라 ISP와 연결되는 외부 경계 인터페이스다.

따라서 다음 네트워크를 EIGRP에 추가하면 안 된다.

```
network 61.41.162.128 0.0.0.3
```

이를 추가하면 R1은 ISP 방향으로 EIGRP Hello를 전송한다.

그러나 ISP는 EIGRP AS 100에 참여하지 않으며, 이번 구성에서는 외부 연결을 하나의 기본 경로로 표현해야 한다.

정상 구조는 다음과 같다.

```
R2·R3
   ↓ EIGRP로 학습한 기본 경로
R1
   ↓ 정적 기본 경로
ISP
```

# 14. EIGRP 이웃 관계 확인

모든 라우터에서 다음 명령을 실행한다.

```
show ip eigrp neighbors
```

## R1 예상 이웃

```
211.242.181.50 → R2 Serial1/1
```

R1은 R2와만 직접 연결되어 있으므로 이웃이 한 개만 나타나는 것이 정상이다.

## R2 예상 이웃

```
211.242.181.49 → R1 Serial1/0
211.242.181.54 → R3 Serial1/1
```

## R3 예상 이웃

```
211.242.181.53 → R2 Serial1/0
```

---

## 14.1 이웃이 나타나지 않을 때

다음 순서로 확인한다.

```
1. 직결 Ping이 성공하는가?
2. 양쪽 인터페이스가 up/up인가?
3. 양쪽 EIGRP AS가 100인가?
4. 해당 직결망이 network 명령에 포함됐는가?
5. 서브넷 마스크가 양쪽에서 같은가?
6. passive-interface가 적용되지 않았는가?
7. Serial DCE clock rate가 설정됐는가?
```

확인 명령:

```
show ip protocols
show running-config | section router eigrp
show ip interface brief
show controllers serial 1/0
```

# 15. EIGRP 라우팅 테이블 확인

```
show ip route eigrp
```

## R1에서 학습해야 하는 네트워크

```
D 211.242.181.16/28 → R2 방향
D 211.242.181.32/28 → R2 방향
D 211.242.181.52/30 → R2 방향
```

## R2에서 학습해야 하는 네트워크

```
D 211.242.181.0/28  → R1 방향
D 211.242.181.32/28 → R3 방향
```

## R3에서 학습해야 하는 네트워크

```
D 211.242.181.0/28  → R2 방향
D 211.242.181.16/28 → R2 방향
```

# 20. 기본 경로를 EIGRP로 재배포

R2와 R3는 ISP와 직접 연결되어 있지 않다.

따라서 R1의 정적 기본 경로를 EIGRP AS 100으로 재배포해야 한다.

R1에서 다음 명령을 실행한다.

```
enable
configure terminal
!
router eigrp 100
 redistribute static
!
end
```

확인:

```
show ip protocols
```

다음 내용이 나타나야 한다.

```
Routing Protocol is "eigrp 100"
Redistributing: static
```

일부 IOS에서 재배포 Metric이 필요하다고 표시되면 다음처럼 Seed Metric을 지정할 수 있다.

```
router eigrp 100
 default-metric 100000 100 255 1 1500
 redistribute static
```

# 마무리

이번 파일의 통신 장애는 단일 EIGRP 오타 때문이 아니라, 네트워크 구축이 완료되지 않은 초기 상태에서 발생한 복합적인 문제다.

핵심 구성 순서는 다음과 같다.

```
인터페이스 IP와 no shutdown
→ Serial DCE clock rate
→ PC와 서버의 IP·Gateway·DNS
→ EIGRP AS 100과 정확한 network 명령
→ R1의 정적 기본 경로
→ redistribute static
→ DNS·HTTP·FTP 서비스 검증
→ 설정 저장
```

특히 이번 실습에서 가장 중요한 부분은 내부 동적 라우팅과 외부 기본 경로의 역할을 구분하는 것이다.

```
내부 네트워크 경로:
EIGRP AS 100으로 구체적인 /28, /30 경로 교환

외부 네트워크 경로:
R1의 정적 기본 경로로 ISP 전달

R2·R3의 외부 경로:
R1이 정적 기본 경로를 EIGRP로 재배포
```

이 구조를 이해하면 기업 지사망에서 내부 라우팅 프로토콜과 인터넷 경계 라우팅을 어떻게 분리하는지까지 함께 이해할 수 있다.
